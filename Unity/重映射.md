# Shader 核心数学技巧：重映射 (Remapping)

> [!abstract] 核心公式
> **公式：** `Output = Input * 0.5 + 0.5;`
> **作用：** 将数值范围从 `[-1, 1]` 线性压缩并平移到 `[0, 1]` 之间。

## 为什么要进行重映射？
在 3D 图形学中，方向向量（如法线、光照方向）的 X、Y、Z 轴分量范围通常是 `[-1, 1]`，包含负数。
然而，**颜色 (RGB)**、**贴图坐标 (UV)** 和 **屏幕显示** 这三个“接收方”底层**只认 0 到 1 的正数**（不接受负数）。
当我们想把“方向数据”塞进“颜色或 UV 数据”时，就必须使用 `* 0.5 + 0.5` 这个万能钥匙进行转换。

---

## 四大经典应用场景

### 1. Matcap 材质采样 (转换法线为 UV)
* **需求：** 将相机的观察空间法线（3D 方向）转为 2D 贴图 UV，用来在圆球贴图上取色。
* **代码：** `half2 uv = normal_viewspace.xy * 0.5 + 0.5;`
* **结果：** 面向屏幕最左边的点 (-1) 映射为 UV 的 0（取图左边缘），正前方 (0) 映射为 0.5（取图正中心）。

### 2. 存储法线贴图 (Normal Map)
* **需求：** 图片格式 (PNG/TGA) 的 RGB 通道只能存 0~255（对应 0~1），无法存负数法线。
* **机制：** 3D 软件在导出法线贴图时，底层会自动执行 `normal * 0.5 + 0.5`。
> [!info] 为什么法线贴图都是蓝紫色的？
> 平坦表面的法线直指正前方，即 (0, 0, 1)。
> 套用公式：X (0 -> 0.5), Y (0 -> 0.5), Z (1 -> 1)。
> 最终存进图片的 RGB 颜色为 `(0.5, 0.5, 1.0)`，这个颜色在视觉上正是标志性的**蓝紫色**。

### 3. 半兰伯特光照 (Half-Lambert)
* **需求：** 拯救卡通渲染中死黑的背光面阴影。
* **痛点：** 标准光照计算 `dot(N, L)` 的背光面结果是负数，会被截断为 0，导致纯黑。
* **代码：** `half NdotL = dot(normal, lightDir) * 0.5 + 0.5;`
* **结果：** 背光面的数值从负数平滑过渡到 0 ~ 0.5，让阴影有了灰度变化，模型看起来更柔和通透（Valve 公司在《半条命》中发明）。

### 4. 可视化调试 (Shader Debugging)
* **需求：** 写代码时光照不对，想把法线直接输出到屏幕上检查（查 Bug）。
* **痛点：** 屏幕无法显示“负数颜色”，朝向负坐标轴的法线全都会变成死黑。
* **代码：** `return fixed4(normal * 0.5 + 0.5, 1);`
* **结果：** 所有的法线都被映射成了彩色，你可以通过红绿蓝的分布，直观看出法线数据是否错误或者产生形变。

---

> [!tip] 逆向操作：法线贴图解包
> 既然存图片时用了 `* 0.5 + 0.5`，那在 Shader 里读取图片时，就需要把 `[0, 1]` 变回 `[-1, 1]`。
> 逆向公式为：**`normal = tex2D(_NormalMap, uv).rgb * 2.0 - 1.0;`**
> （注：在 Unity 中通常直接使用内置函数 `UnpackNormal()` 代替手写。）
