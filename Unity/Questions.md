# 向量分量操作与数据打包技巧
<br>

- 材质面板上，每一张贴图下方默认都会跟两个设置：
	- Tiling（缩放/平铺）：X Y
	- Offest（偏移）：X Y
  - 可是为了把4个数字一次性传递给显卡，Unity潜规则：只要声明一个 MainTex 贴图，系统会自动寻找一个配套float4的四维向量变量 MainTex_ST 这里面有：
	  - . x = Tiling的X
	  - . y = Tiling的Y
	  - . z = Offest的X
	  - . w = Offest的Y
- 2D贴图中，流动速度只需要两个方向：U方向（横向）和 V方向（纵向）
- 如果有两张以上的贴图，则_Speed2.xy_Speed2.zw  
- 将 Unity 材质面板上的 Tiling（缩放）和 Offset（偏移）数值，真正应用到 UV 坐标上：
  只要希望材质面板上的TO属性能对贴图产生影响，就必须执行乘加运算：
	- o.uv = xz_uv * _MainTex_ST.xy + _MainTex_ST.zw;
	- $$UV_{final} = UV_{base} \times Scale + Translate$$

# 利用空间坐标生成虚拟 UV（防贴图滑动穿帮）
<br>

### 一、 核心知识点：世界坐标去位移（锚定世界投影 UV）

**本质原理**：通过 `(世界顶点坐标 - 世界中心坐标)`，获取一个**不受物体移动（位移）影响、且方向始终与世界坐标系对齐**的相对向量，以此作为计算贴图 UV 的基础。

#### 核心应用场景（什么时候用？）

##### 1. 科幻护盾、全息投影、魔法能量场（Hologram / Shield）

- **需求**：需要一条扫描线或六边形网格从上往下扫，且不希望由于角色身上复杂的模型 UV 导致纹理断裂。
    
- **效果**：流光方向永远对齐世界坐标轴（比如永远垂直于地面）。无论角色跑得多快，护盾纹理都紧紧跟在身上（无滑动）；但如果角色倒地或弯腰（发生旋转），光效依然保持相对于世界的自上而下，视觉上非常符合“物理能量场”的设定。
    

##### 2. 无缝地形或大尺寸物件的材质拼接（World Aligned Texture）

- **需求**：在搭建场景时，拼接的墙壁、地面或大石头如果直接用模型本身 UV，接缝处的贴图纹理会对不上。
    
- **效果**：使用这种基于世界坐标的投影，可以让相连的独立物体贴图完美连续。减去 `pivot_world` 可以确保这些物体在编辑器中被拖动或由代码动态生成时，贴图不会在表面“游动”。
    
- _注_：在 Unreal Engine 材质蓝图中，这对应自定义 `WorldAlignedTexture` 节点防止移动穿帮的底层逻辑；在 Unity URP Shader Graph 中，对应使用 `Position (World)` 节点减去 `Object Node (Position)`。
    

##### 3. 角色受击/传送时的定向消融（Directional Dissolve）

- **需求**：怪物死亡时，想要一个“从脚底一路烧到头顶”的定向消融特效。
    
- **效果**：通过 `pos_world.y - pivot_world.y`，你能准确拿到物体从底部到顶部的高度差数据。这个数据不受物体站在山顶还是谷底（绝对高度）的影响，非常适合配合时间变量（`_Time`）作为消融的阈值。
    

##### 4. 规避劣质或缺失的模型 UV

- **需求**：拿到一个程序化生成的网格（Procedural Mesh）或者美术没展好 UV 的白模，但需要立刻给它贴上一个流动的噪声贴图（Noise）做特效验证。
    
- **效果**：直接绕开模型自带的 `v.texcoord`，用这套算法强行在世界空间给它“投射”一套方向统一且跟手的虚拟 UV。
    

### 二、 进阶补充：角色旋转时的贴图滑动问题 (Local Space Projection)

**问题现象**：

虽然 `pos_world - pivot_world` 解决了物体**平移（移动）**时的贴图滑动，但因为相减后的向量依然是**世界坐标系朝向**的，当你的角色发生旋转（Rotation，比如弯腰、翻滚、倒地）时，模型网格会穿过这个固定朝向的虚拟投影，导致贴图在表面再次发生滑动。

**解决思路：回归模型空间（Object Space / Local Space）**

如果你希望这层特效不仅跟着角色跑，还要**完全“焊死”在角色身上**（无论怎么旋转都不滑动），你需要彻底摒弃世界坐标，直接使用模型的本地顶点坐标（Local Position）来生成 UV。

### 核心代码实现与对比

**方案 A：世界坐标锚定（防平移，不防旋转）**

```hlsl
// 1. 顶点着色器 (vert) 阶段收集数据
// 获取顶点世界坐标
o.pos_world = mul(unity_ObjectToWorld, v.vertex).xyz;
// 获取物体中心点世界坐标 (将本地原点 0,0,0,1 转换到世界) 1是点 0是向量
o.pivot_world = mul(unity_ObjectToWorld, float4(0.0, 0.0, 0.0, 1.0)).xyz;

// 2. 片元着色器 (frag) 阶段生成 UV
// 计算去位移后的投影 UV (以 XY 平面为例)
float2 uv = (i.pos_world.xy - i.pivot_world.xy) * _Tiling;
```

**方案 B：本地坐标投影（防平移，且防旋转）**

```hlsl
// 1. 顶点着色器 (vert) 中直接传递本地坐标：
o.pos_local = v.vertex.xyz; 

// 2. 片元着色器 (frag) 中直接使用：
// 本地坐标原点天生就是物体的 Pivot，且方向随物体旋转！
float2 uv = i.pos_local.xy * _Tiling; 
```

### 三、 总结：如何选择你的 UV 生成方案？

|**业务需求**|**最佳 UV 生成方案**|**原理与视觉效果说明**|
|---|---|---|
|**美术精心画好的常规纹理**（衣服、皮肤）|`v.texcoord` (自带UV)|绝对精准随形，但极度依赖模型 UV 拆分质量，必然存在接缝。|
|**静态场景的地形/墙壁无缝拼接**|`pos_world` (纯世界投影)|跨物体无缝拼接，方向绝对统一。**致命弱点：物体一动，贴图就会在表面滑动。**|
|**永远朝向地面的魔法护盾 / 垂直扫描线**|`pos_world - pivot_world`|消除平移影响，保留世界朝向。无视接缝，跟着角色跑，但**角色旋转时贴图会在表面滑动**（对能量罩通常是加分项）。|
|**无视原 UV 接缝，且死死贴在身上的能量纹路**|`pos_local` (本地坐标投影)|本地坐标自带原点锚定和旋转跟随。**彻底固定在模型上，完全不滑动。**|

> 💡 **笔记要点**：图形学中没有完美的单一解法。写 Shader 时，思考**“特效纹理应当锚定在哪个坐标系（World 还是 Object），是否需要跟随旋转”**，是决定视觉表现正确与否的最核心前提。

# 安全冗余
<br>

##### 1. 裁剪阈值

1. **保证初始状态完全显示（下限定为 -0.1）** 如果下限刚好设为 0.0，由于计算机底层处理浮点数（小数）时存在精度误差，某些刚好是黑色的像素点计算后可能会变成 -0.00001。这就导致进度条还没开始拉，模型表面就已经出现莫名的破洞了。 把下限设为 -0.1，意味着初始计算时相当于“加上 0.1”，这保证了所有像素的最终值绝对大于 0，模型得以 100% 完整显示。

2. **保证最终状态完全消失（上限定为 1.1）** 同理，如果上限死死卡在 1.0，可能会有极少数纯白像素在经历公式相减后，结果无限趋近于 0 但就是不小于 0，导致溶解到最后，模型总会剩下一点点渣滓消不掉（就像去不掉的头皮屑）。 把上限推高到 1.1，确保了当溶解拉到尽头时，所有的点都会被彻底 `clip` 杀掉，模型消失得干干净净。
<br>

##### 2. Smoothstep函数
<br>
在 Shader 中，除了非黑即白的 `clip()`，我们经常需要做柔和的渐变混合。这时候最常用的数学函数是 `smoothstep(min, max, x)`。

正常逻辑下，我们可能想让数值 $x$ 在 $0.0$ 到 $1.0$ 之间平滑过渡。但因为精度误差，当 $x$ 极其接近 $0.0$ 或 $1.0$ 时，可能会出现微小的噪点或者硬边。

- **冗余操作**：资深 Shader 程序员经常会写成 `smoothstep(-0.01, 1.01, x)`。故意把区间撑大一点点，确保在达到极值时，过渡能够绝对干净、纯粹，不留任何视觉瑕疵。
<br>
##### 3. 深度冲突 (Z-Fighting) 与深度偏移 (Depth Bias)

在构建游戏场景或处理角色武器挂载系统时，如果有两个模型面（比如墙壁和贴在地上的海报，或者紧贴着身体的武器配件）在空间里的深度坐标（$Z$ 值）完全一样，GPU 就会“懵”，不知道该把谁画在前面，从而导致画面疯狂闪烁。

- **冗余操作**：为了解决这个问题，我们会给上层的材质添加一个极小的 **深度偏移（Depth Bias）**（比如加上 $0.001$）。这个微小的数值就是一个安全冗余，它不会在视觉上改变物体的位置，但能在 GPU 渲染排序时明确分出先后，彻底消除闪烁。
<br>
##### 4. 顶点动画与包围盒剔除 (Frustum Culling)

游戏引擎为了节省性能，相机会进行“视锥体剔除”：只要一个物体的包围盒（Bounding Box，一个包裹着模型的虚拟方块）离开了屏幕范围，引擎就会停止渲染它。 但是，如果你写了一个让草地随风摇摆、或者水面起伏的顶点着色器（Vertex Shader），顶点的真实位置会超出原本静止状态下的包围盒。这就导致：相机的边缘明明还能看到飘过来的草，但引擎判定包围盒已经出画了，模型会在屏幕边缘突然闪现消失。

- **冗余操作**：在引擎设置中，我们需要手动将这类材质的**包围盒放大（Bounds Padding）**，比如四周各加长 10%。这多出来的体积就是安全冗余，确保动画播放到极限距离时，也不会被错误剔除。
<br>
##### 5. 贴图采样防溢出 (Texture Clamping)

当你对贴图进行采样时，UV 坐标的合法范围是 $0.0$ 到 $1.0$。如果你在 Shader 里对 UV 进行了复杂的数学扭曲计算，某些边缘像素的 UV 可能会变成 $-0.002$ 或 $1.005$。

如果贴图设置的是循环模式（Repeat），边缘就会突然出现图像另一端的像素（产生一条违和的黑线或亮边）。

- **冗余操作**：在关键的采样计算中，我们常使用 `saturate(uv)` 或者设置边界限制（Clamp），强制把数值死死钳制在一个安全的范围内，防止哪怕 $0.001$ 的溢出导致画面穿帮。

# sRGB & RGBA

#### sRGB 与 RGBA 的区别与应用

在计算机图形学和引擎开发中，sRGB 和 RGBA 描述的是完全不同维度的两个概念：
*   **sRGB** 决定了颜色**“看起来应该是什么样”**（色彩标准与滤镜）
*   **RGBA** 决定了这张图片**“能装下多少种数据”**（数据通道与容器）

#### 1. sRGB：色彩空间 (Color Space)

sRGB 是一个国际颜色标准，核心作用是解决“Gamma 校正”问题（给画面加/解滤镜，以适应人眼和老式显示器的物理特性）。

*   **本质：** 一种色彩显示标准（自带 Gamma 2.2 曲线）。
*   **作用范围：** 它只关心红(R)、绿(G)、蓝(B)这三种颜色混合出来的结果，在不同屏幕上看起来是不是统一的、符合人眼视觉的。
*   **引擎导入规范：**
    *   **必须勾选 sRGB（颜色类贴图）：** 漫反射贴图 (Albedo/Diffuse)、UI 界面图片、角色皮肤纹理。这些是真实的颜色，是**给人眼看的**。
    *   **绝对不能勾选 sRGB（数据类贴图）：** 法线贴图 (Normal Map)、粗糙度贴图 (Roughness)、金属度贴图。这些是给机器算的**物理数据**，必须用线性 (Linear) 空间。

#### 2. RGBA：数据通道 (Color Channels)

RGBA 是一种数据存储格式，代表一个像素由 4 个数值（红、绿、蓝、透明度）组成。

*   **本质：** 一种数据存储格式（包含 4 个通道）。
*   **作用范围：** 它不关心这些数值代表什么颜色，只负责把数字客观地存起来。这里的 A 代表 Alpha（透明度）。
*   **引擎导入规范：**
    *   **需要透明效果时：** 树叶、铁丝网、带有半透明边缘的特效材质（如幽灵、护盾），必须保存为支持 Alpha 通道的格式（如 PNG 或 TGA）。
    *   **需要通道打包 (Channel Packing) 时：** 为了节省性能，开发者经常把另一张黑白图片塞进 A 通道里。例如 RGB 存颜色，A 通道存发光遮罩，实现一张贴图提供两种数据。

#### 3. 核心对比总结

| 特性 | sRGB | RGBA |
| :--- | :--- | :--- |
| **解决什么问题** | 保证颜色在显示器上看起来正确、不发灰 | 提供一个额外的通道来存储透明度或自定义数据 |
| **针对的对象** | 仅仅针对图片的颜色数据 (RGB) | 针对图片的像素结构 (红绿蓝 + 透明度) |
| **典型文件格式** | 任何格式都可以是 sRGB（JPG, PNG 等） | 必须支持透明通道的格式（PNG, TGA, TIFF 等） |

**⚠️ 关键注意点：它们可以同时存在** 
在游戏引擎里，你可以导入一张带有透明通道的贴图（格式是 RGBA），同时在设置里勾选它为 sRGB。
此时引擎的底层逻辑是：**Gamma 校正永远只会作用于 R, G, B 这三个颜色通道**。因为 Alpha 通道通常用来表示纯物理的遮罩数据，所以 **Alpha 通道永远是线性的 (Linear)**。

#  插值 (Lerp)

## 1. 核心概念

“插值系数”（常简写为 $t$、$alpha$ 或 $weight$）本质上就是一个**混合比例**或**进度条**。

在写代码或 Shader 时，最常用的函数是**线性插值 (Linear Interpolation)**：

- **Shader 代码：** `lerp(a, b, t)`

- **C# 代码：** `Mathf.Lerp(a, b, t)`


**参数拆解：**

- `a` = 起点状态（如：红色、坐标 A、透明度 $0$）

- `b` = 终点状态（如：蓝色、坐标 B、透明度 $1$）

- `t` = 插值系数（通常是 $0$ 到 $1$ 之间的小数，代表“进度百分比”）

## 2. t 值的直观效果

以混合颜色（a=红，b=蓝）为例：

- **$t = 0.0$** ➡️ 进度 0%，完全输出 **A**（纯红）

- **$t = 1.0$** ➡️ 进度 100%，完全输出 **B**（纯蓝）

- **$t = 0.5$** ➡️ 进度 50%，A 和 B 各占一半（完美的紫色）

- **$t = 0.2$** ➡️ 进度 20%，输出偏红的紫红色（80%红 + 20%蓝）


> **底层数学公式：** $Result = a + (b - a) \times t$

## 3. 用法

1. **纹理与颜色混合 (Texture Blending)：**

	利用一张黑白遮罩图（Mask）作为 $t$。黑色像素区域 ($t=0$) 显示底色/草地，白色像素区域 ($t=1$) 显示花纹/泥土，灰色区域自动产生平滑过渡。

2. **呼吸灯特效 (Transitions)：**

	将时间函数（如 `sin` 波浪线）算出的 $0 \sim 1$ 循环值作为 $t$ 传进去，让材质的自发光（Emission）在暗（a）与亮（b）之间自动来回渐变。
# Z-Buffer

在深度缓冲区（Z-Buffer）中写入物体的深度信息，但不在屏幕上渲染出任何颜色

“隐身并占位”（通常用于遮挡剔除、阴影预处理或一些特殊的遮罩效果）

```hlsl
        Pass
        {
            Cull Off
            ZWrite On
            ColorMask 0

            CGPROGRAM

            float4 _Color;

            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            float4 vert(float4 vertexPos : POSITION) : SV_POSITION
            {
                return UnityObjectToClipPos(vertexPos);
            }

            float4 frag(void) : SV_Target
            {
                return _Color;    
            }

            ENDCG   
        }
```
