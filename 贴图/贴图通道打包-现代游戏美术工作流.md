# 贴图通道打包（Channel Packing）· 现代游戏美术工作流

> [!abstract] 一句话
> **通道打包 = 把多张灰度/数据图塞进同一张贴图的 RGBA 通道里**，用「一张图 + 一次采样」同时拿到多个数值，从而**省显存、省采样器、省带宽**。它不是某种压缩格式，而是「贴图内容的组织方式」。
>
> 现代 PBR 工作流里最核心的两个打包：**① 法线（RG 存 XY）**、**② 遮罩三件套（RMA/ORM）**，其余都是在这基础上按项目需求扩展。

---

## 一、为什么要打包

1. **省显存 / 省采样器**：3 张图 → 1 张图，减少纹理槽位占用（移动端尤其紧张）。
2. **省带宽**：一次 `tex2D` 采样同时拿到多个值（粗糙度、金属度、AO），而不是采样三次。
3. **数据天然适合**：遮罩、ID、法线分量都是 0~1 的数值，各塞一个通道互不干扰。

---

## 二、材质数据打包（PBR 遮罩类）

| 打包方式 | 通道布局 | 用途 |
|----------|----------|------|
| **RMA / ORM / MRAO** | R=粗糙度 G=金属度 B=AO（顺序各厂不同） | 最主流的材质遮罩三件套 |
| **Roughness + Metallic** | R=粗糙 G=金属 | 简化版，AO 单独一张 |
| **AO + Curvature + Thickness** | 各占一通道 | Substance Painter 常见导出，烘焙细节用 |
| **Smoothness（Invert Roughness）** | R=光滑度 = 1 − 粗糙度 | Unity 老 Specular 工作流 / 部分自定义管线 |
| **Cavity + AO** | 分通道 | 增强局部细节遮蔽 |

> [!note] RMA 里的 "A" 是 AO，不是 alpha
> RMA = **R**oughness + **M**etallic + **A**mbient Occlusion。三个灰度图塞进 RGB，**alpha 通道常空着或另放东西**。别和「带 alpha 的透明贴图」搞混。

> [!tip] 命名/顺序坑
> 同样一张 RMA，**Substance Painter、Marmoset、Unity、UE 的通道顺序和命名可能不一致**，接入时先对一下顺序，别把 R/G/B 接反。常见别名：ORM、MRAO、OcclusionRoughnessMetallic——本质同一个东西。

---

## 三、法线类（含「塞额外数据」）

| 打包方式 | 通道布局 | 说明 |
|----------|----------|------|
| **法线 RG 双通道** | R/G 存法线 XY，Z 由 Shader 重建 | 单位向量恒等 Z = √(1−x²−y²)，引擎里走 BC5 |
| **Normal + Height** | RG=法线，B=高度 | 高度用于视差 / 置换 |
| **Normal + AO** | RG=法线，A=AO | 常用，省一张 AO |
| **Normal + Roughness** | RG=法线，B=粗糙度 | 移动端减贴图常用 |
| **Detail Normal（细节法线）** | 单独一张，UV 平铺不同 | 与主法线叠加 |

> [!note] 为什么法线只存 RG
> 法线是单位向量，三个分量平方和为 1，知道 XY 就能反推 Z，所以第三通道可以省出来放别的东西。

---

## 四、蒙版 / ID / 权重类

| 打包方式 | 通道布局 | 用途 |
|----------|----------|------|
| **ID Map（物体 ID）** | R/G/B 各存一个区域 ID | 后期分级、智能蒙版、材质区域划分 |
| **Attribute Mask（属性遮罩）** | R=皮肤 G=毛发 B=布料 A=SSS 区域 | 角色材质里控制 SSS 强度、法线强度、粗糙度 |
| **材质混合权重** | 各通道=各材质权重（和为 1） | 雪/土/苔藓/磨损等自动混合（RVT / 分层材质） |
| **RGB 蒙版** | 每个通道一个布尔遮罩 | 划分区域做不同处理 |

---

## 五、特殊功能数据贴图

| 打包方式 | 说明 |
|----------|------|
| **Flow Map** | R/G 存 2D 流动方向向量（水、岩浆流动） |
| **置换 / 高度（单通道）** | 灰度，走 BC4 |
| **Emissive** | 全 RGB 自发光颜色（**不打包，独立一张**） |

---

## 六、顶点色打包（非贴图，但同思路）

顶点色的 RGBA 也常被用来「打包」数据：

- 烘焙光照 / AO / 阴影
- 顶点 ID / 区域遮罩
- 风场权重（植被摆动）、流动强度
- 材质混合权重

> [!tip] 权衡
> 好处：零额外贴图、零额外显存。坏处：分辨率受顶点数限制，顶点稀疏处信息粗糙。

---

## 七、空间打包（顺带提，非通道）

严格说不是通道打包，但常一起被问：

- **Texture Atlas / Trim Sheet**：多个贴图塞进一张图的不同 UV 区域。
- **多套 UV**：一套模型用多套 UV 分别放光照、细节、三平面。

两者节省的也是「贴图数量」，和通道打包目标一致。

---

## 八、Substance Painter：烘焙 → 导出打包实战

SP 的完整链路是「**烘焙 mesh maps → 材质分层 → 导出时按 Output Template 做通道打包**」。打包动作主要发生在**导出阶段**，靠输出模板决定哪些通道塞进哪张图。

### 8.1 烘焙产出（Bake Mesh Maps）

烘焙是把高模细节烘到低模上，SP 会生成一批 mesh map：

| Mesh Map | 说明 | 后续去向 |
|----------|------|----------|
| **Normal** | 切线空间法线（核心） | 直接导出，或参与打包 |
| **World Space Normal** | 世界空间法线 | 特效 / 三平面用，通常不导出 |
| **AO** | 环境光遮蔽 | 打包进遮罩图 |
| **Curvature** | 曲率（凸起 / 凹陷） | 生成磨损 / 边缘遮罩 |
| **Thickness** | 厚度 | 半透光（SSS / 皮肤）遮罩 |
| **Position** | 世界位置 | 渐变 / 区域遮罩 |
| **ID** | 颜色 ID 遮罩 | 分区上色 |

> [!tip] 遮罩主力三件套
> 曲率、厚度、AO 是「生成遮罩」的主力，但**导出时未必各自一张**——常被打包进一张遮罩图，或根本不导出（只在 SP 内部做遮罩用）。

### 8.2 导出打包：三个关键预设

SP 的 **Export Textures → Output Template** 决定打包结果，最常用三个：

| 预设 / 目标 | 打包贴图 | 通道顺序 |
|-------------|----------|----------|
| **Unreal (Packed)** | 一张 Packed | **R=AO，G=Roughness，B=Metallic**（即 ORM） |
| **Unity HDRP** | Mask Map | **R=Metallic，G=AO，B=Detail Mask，A=Smoothness** |
| **Unity Standard / URP** | MetallicSmoothness | **R=Metallic，A=Smoothness**（AO 另走 G 通道或独立） |

> [!warning] 顺序千万别背错
> 同样是「金属 / 粗糙 / AO」三件套，**UE 是 ORM（AO 在 R），Unity HDRP 是 Metallic 在 R**。这就是上一节「各厂顺序不同」的落点——导出时选对模板，比手动记顺序靠谱。
>
> 自定义 Output Template 时，逐个通道点选，别手滑把 R/G/B 接反。

### 8.3 四个必设项

| 设置 | 怎么选 |
|------|--------|
| **法线方向（Green Channel）** | **UE 用 DirectX，Unity 用 OpenGL**。选反了法线凹凸会反，这是最常见的坑 |
| **sRGB / Linear** | Base Color 按 sRGB 出；法线、遮罩、ID 按 Linear。但**物理文件像素值一样**，真正生效的是引擎导入时勾不勾 sRGB |
| **Padding（边缘扩展）** | 用 Alpha / Dilation 方式，别用纯黑，防止 mipmap 低层级时边缘漏色（黑边） |
| **尺寸 / 格式** | 颜色图 PNG 8bit；HDR / 高精度用 EXR；遮罩图尺寸可比颜色图更小 |

### 8.4 接进引擎（承上）

导出打包好的贴图落进引擎后，回到下节「引擎处理要点」：

- 数据图**关 sRGB**，颜色图勾 sRGB；
- 按通道数选压缩（Packed 3~4 通道 → BC7 / TC_Masks）；
- UE 里用 **ComponentMask** 取 R/G/B 接 AO / Roughness / Metallic。

---

## 九、引擎处理要点（Unity / UE 通用规律）

不管哪种打包，两引擎遵守同一套：

| 要点 | 规则 |
|------|------|
| **关 sRGB** | 除纯颜色（BaseColor / Emissive）外，法线、遮罩、ID、高度、Flow 全是**线性数据**，勾 sRGB 就会 gamma 出错 |
| **按通道数选压缩** | 单通道 → BC4 / TC_Grayscale；双通道 → BC5 / TC_Normalmap；3~4 通道 → BC7 或 BC3 |
| **Shader 取通道** | UE 用 **ComponentMask** 节点；Unity 用通道抽取，分别接对应输入 |

### Unity 具体约定

- **HDRP Mask Map**：R=Metallic、G=AO、B=Detail Mask、A=Smoothness（各管线约定可能不同，以项目 Shader 为准）。
- 导入时**取消 sRGB**；压缩选 High Quality（BC7）或 Normal（BC3）。

### UE 具体约定

- UE 惯例是「**一张图一个用途** + 材质节点合成」，而非美术手动打包 RMA。
- 若确用打包贴图（移动端 / 风格化项目常见）：压缩用 **TC_Masks（BC7）** 或 TC_Default，**取消 sRGB**，材质里用 **ComponentMask** 分别取 R/G/B 接对应输入。

---

## 十、一句话记忆

- **数据贴图（法线/遮罩/ID/高度/Flow）→ 关 sRGB，别用 BC1/BC5 这种通道数不对的格式。**
- **纯颜色（BaseColor/Emissive）→ 勾 sRGB。**
- 最核心的两个打包：**法线 RG** + **遮罩 RMA**。
