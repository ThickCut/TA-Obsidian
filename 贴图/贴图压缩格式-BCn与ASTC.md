# 贴图压缩格式（BCn / ASTC / ETC）

> [!abstract] 一句话
> **BC（Block Compression，块压缩）是桌面/主机 GPU 的纹理压缩格式家族**——把贴图按 4×4 像素一块一块压缩，运行时**不解压、直接由 GPU 硬件采样**，所以又省显存又省带宽。BC1 到 BC7 对应不同用途（颜色/alpha/法线/HDR）。移动端用的是另一套：ASTC、ETC2、PVRTC。

---

## 一、先搞懂：什么是「压缩贴图」

普通 PNG/JPG 是**文件压缩**，进显存前必须解码成完整像素（RGBA32），显存占用反而变大。

GPU 压缩格式（BCn / ASTC / ETC）不一样：

| | 文件压缩（PNG/JPG） | GPU 压缩（BCn/ASTC） |
|---|---|---|
| 压缩单位 | 整图熵编码 | 固定 **4×4 像素块** |
| 是否要解码 | 进显存前要解成 RGBA | **不需要**，GPU 直接采样 |
| 显存占用 | 大（解码后全尺寸） | 小（保持压缩态） |
| 带宽 | 高 | 低（读的是压缩数据） |
| 随机访问 | 不行 | 行（按块定位） |

> [!note] 核心概念
> 桌面/主机的这套压缩格式统称 **BC（Block Compression）**，因为算法都是「把每 4×4 的像素块，用少量端点和每像素索引来近似」。老名字叫 **DXT（DirectX Texture compression）**，两者几乎是一回事：DXT1=BC1，DXT3=BC2，DXT5=BC3。

---

## 二、BC 家族逐个数

| 格式 | 别名 | 每块像素 | 压缩比 | 通道 | 用途 |
|------|------|----------|--------|------|------|
| **BC1** | DXT1 | 4×4 | 8:1 | RGB + 1bit alpha | 无 alpha 或纯 0/1 alpha 的漫反射 |
| **BC2** | DXT3 | 4×4 | 4:1 | RGBA（4bit alpha） | 低精度 alpha，较少用 |
| **BC3** | DXT5 | 4×4 | 4:1 | RGBA（8bit alpha） | 带 alpha 的漫反射 |
| **BC4** | ATI1 | 4×4 | 2:1 | 单通道 R | 高度、粗糙度等灰度图 |
| **BC5** | ATI2 | 4×4 | 2:1 | 双通道 RG | **法线**（存 XY）、双通道数据 |
| **BC6H** | — | 4×4 | 6:1 | RGB 半浮点 | **HDR** 颜色（HDRI、光照） |
| **BC7** | — | 4×4 | 4:1 | RGBA 高质量 | 高质量通用（桌面端画质最优） |

### 怎么记 / 怎么选

- **颜色图**：无 alpha → BC1；有 alpha → BC3；追求画质 → **BC7**。
- **法线**：只用两通道 → **BC5**（别用 BC3 浪费一个通道 + 精度差）。
- **灰度单通道**（高度/粗糙度/AO）→ **BC4**。
- **HDR**（自发光/环境贴图）→ **BC6H**。

> [!tip] 为什么法线用 BC5 而不是 BC3
> BC3 用 G 通道近似存 alpha，法线放进去会丢精度、出现明显 banding。BC5 用**两个完整通道**分别存法线的 X、Y，精度高很多。

## 三、移动端：另一套格式

桌面 BC 在移动 GPU 上**不通用**，移动端有自己的格式：

| 格式 | 说明 |
|------|------|
| **ASTC** | **现代移动端事实标准**。块大小可调（4×4 / 6×6 / 8×8…），质量与压缩率可平衡，iOS + Android 高端通用 |
| **ETC2 / EAC** | Android OpenGL ES 3.0 起步的兜底格式（EAC 用于单/双通道） |
| **PVRTC** | iOS 老机型兜底，已被 ASTC 取代，基本只剩兼容 |

> [!note] ASTC 的块大小
> 块越大压缩率越高、质量越低。常用 6×6 做基线，4×4 更清晰但更大，8×8 更小但更糊。

---

## 四、容器 / 打包格式（承载这些压缩块的文件）

GPU 格式是「进显存的形态」，外面还要一个文件容器包起来：

| 容器 | 说明 |
|------|------|
| **DDS** | DirectX 老牌容器，能直接存 BCn 块，桌面工具链通用 |
| **KTX / KTX2** | Khronos 跨平台标准；**KTX2** 是 Vulkan/移动端首选，可内嵌 Basis 超压缩 |
| **Basis Universal（.basis）** | 超压缩中间格式，一次压缩可转码出多种 GPU 格式，适合 Web/流式 |
| **.astc** | ASTC 既是一种算法，也常作为直接打包文件 |

引擎内部还会再包一层（Unity 的 `.ktx/.astc` 资产、UE 的 `.uasset`），本质还是上面的格式。

## 五、Unity / UE 里的落点

| 需求 | Unity | Unreal |
|------|-------|--------|
| 普通漫反射 | High Quality → BC7 / Normal → BC3 | TC_Default |
| 法线 | 勾 Normal Map → BC5 | TC_Normalmap → BC5 |
| 单通道（粗糙度/高度） | 打包 + 关 sRGB | TC_Grayscale（BC4） |
| HDR | BC6H | TC_HDR（BC6H） |
| 移动端 | ASTC（可 per-platform override） | ASTC（+ Oodle） |
| 减包体 | **Crunch**（磁盘二次压缩） | **Oodle Texture / RDO** |

> [!warning] 两个通用坑
> 1. **数据贴图关 sRGB**：法线、粗糙度、金属度、AO、高度、Flow 全是线性数据，勾 sRGB 会 gamma 出错。
> 2. **按通道数选格式**：单通道 BC4、双通道 BC5、3~4 通道 BC3/BC7，选错了要么浪费要么坏值。

---

## 六、一句话记忆

- **BC = 桌面/主机 GPU 的块压缩家族**（DXT 是老名字），4×4 一块，硬件直接采样。
- **BC1 颜色 / BC5 法线 / BC4 灰度 / BC6H HDR / BC7 高质量**，各司其职。
- **移动端用 ASTC**（主流）/ ETC2（兜底）/ PVRTC（老 iOS），BC 在手机上跑不了。
- 外面再套 **DDS / KTX2 / Basis** 容器。
